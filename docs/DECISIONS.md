## Deviations from the spec

- **Core holds the orchestrator.** `analyze()` lives in `packages/core/src/analyze.ts` with its dependencies (model call, consent, lazy cloud init) injected, so the failure ladder is unit-tested without a browser. `apps/extension/lib/engine.ts` wires it to Firebase and Chrome storage.
- **`@satark/core/pure` entry.** The service worker and the extractor import from it so no Firebase code is bundled into them (the worker is about 7 kB).
- **Lazy cloud setup.** `initFirebase()` only creates the app, App Check (auto refresh off) and the AI instance. `ensureCloud()` turns App Check refresh on and signs in anonymously, and is called by `analyze()` only right before a cloud-capable route (anything other than `ONLY_ON_DEVICE`). Private mode and on-device checks therefore make no content-bearing request.
- **Unconfigured builds.** Without `VITE_FIREBASE_*` values the app is created with placeholder config so `ONLY_ON_DEVICE` still works; the cloud is treated as off (router rule 2) and the panel says the build has no cloud setup.
- **Failure ladder tweaks.** A size error retries the same route once at 60% of the input; a parse error retries once with "Return valid JSON only"; then the route switches as the spec says. At most 5 rounds per check.
- **Lookalike hosts.** Edit distance 1 for brand tokens of 5-7 letters, 2 for 8+ letters, and exact brand tokens on someone else's domain (for example `sbi-kyc-update.com`) also count. A short list of ordinary words (`apply`, `amazing`, ...) is excluded to cut false positives.
- **Highlights across nodes.** The extractor builds one normalized string with a character-to-node map, so quotes that span several text nodes (bold words, links) are highlighted. This was a P1 item in the spec.
- **Guardian mode (P1) included, minimal.** With the optional `<all_urls>` permission granted from Options, the worker runs Tier-0 on each loaded page and sets a badge. No AI and no network.
- **"Copy a warning for family" (P1) included.**
- **Dark-pattern heuristic (P1).** The extractor counts checkboxes ticked by default whose label sells an extra (insurance, protection, subscription, donation, ...): 15 points each, max 30. Fake countdowns were already a Tier-0 signal.
- **Evaluation page (P1).** `eval.html` (linked from Options > Developer) runs the 30 samples in `eval/samples.json` through `ONLY_ON_DEVICE` and `ONLY_IN_CLOUD`. Cloud runs skip the consent sheet because the samples are synthetic, and nothing is written to the receipt log. Scoring is the pure, tested `scoreEval()` in core. Real numbers still have to be produced on qualifying hardware.
- **Firestore sync (P1), opt-in.** `lib/sync.ts` writes only `settings` (mode, language), `counters` and `updatedAt` to `users/{uid}`, matching `firestore.rules`. Firestore is a lazily loaded chunk (about 400 kB minified) fetched only when sync is on. Turning sync off deletes the document. This is a metadata request, not a model call, so it does not go through `analyze()`.
- **Hosted playground (P1).** `apps/site/playground.html` bundles `@satark/core/pure` with esbuild and runs Tier-0 and the redaction preview in the visitor's tab. It makes no network request and runs no AI: a web AI path would need its own App Check (reCAPTCHA) setup. The AI check stays in the extension.
- **Visual design.** Researched side-panel guidance and soft-palette accessibility: warm paper background, dark warm ink, one muted sage-teal accent, pastel only on verdict and quick-check surfaces, serif display headings, no gradients, glow or purple. Text colours are WCAG AA (4.5:1 or better) and control borders are 3:1 or better; the lightest neutrals are never used for text.
- **Production App Check (P2).** `functions/src/index.ts` (`appCheckExchange`, HTTPS, Node 22) verifies the caller's Firebase ID token, applies a per-user fixed-window limit (20 tokens per hour, stored in `appCheckQuota/{uid}`, no client access), checks the extension origin against `SATARK_ALLOWED_ORIGINS`, and mints a 30-minute App Check token with the Admin SDK. The extension's `CustomProvider` calls it when `VITE_APPCHECK_EXCHANGE_URL` is set; a debug token in Options still overrides it for development. App Check must **not** be enforced on Authentication, or the extension could not sign in to reach the function. Needs the Blaze plan. Pending: deploy and test from the real extension origin.
- **Translations (P2).** 58 explanation languages (`LANGUAGES` in `packages/core/src/translate.ts`), including Hindi, Bengali, Tamil, Telugu, Marathi, Gujarati, Kannada, Malayalam, Punjabi, Odia, Assamese, Urdu and Nepali, plus a "Same as my browser" option. Settings now store a BCP 47 code; older saved names such as "Hindi" are still understood. The list is not hard-coded to what Chrome's Translator supports (its docs could not be fetched from the build sandbox): the extension asks `Translator.availability()` at runtime for each language. If on-device translation is unavailable, the result offers "Explain in <language> using the cloud" (redacted, with consent), so every listed language works through one route or the other. Right-to-left languages (Arabic, Urdu, Persian, Hebrew) get `dir="rtl"`; generated text carries a `lang` attribute; quotes use `dir="auto"` so they follow the page's script. On-device verdicts are translated with Chrome's built-in Translator API (on-device, English to the chosen language); cloud verdicts already come back in that language from the prompt, which names the language and code. Quotes are never translated so they still match the page and pass verification. If the language pack must be downloaded, the user clicks "Show in <language>" (user activation). Pending: check Hindi pack availability on real Chrome.
- **Firefox build (P2).** `pnpm zip:firefox` makes a Manifest V3 add-on: WXT maps the side panel to `sidebar_action`, the worker opens it with `sidebarAction.open()`, `sidePanel` is dropped from permissions, and `browser_specific_settings` declares `websiteContent` data collection (redacted text goes to the cloud after consent). Firefox has no Prompt API, so every AI check uses the cloud route; the Translator API is also absent, so the cloud prompt handles languages. Minimum Firefox 140 (CSS Custom Highlight API). `pnpm zip:firefox` also writes the full-monorepo source ZIP that Mozilla asks for. Pending: `web-ext lint` (runs in CI) and a manual run in Firefox.
- **Not built yet (P2):** offscreen document for background checks, community scam-domain reports.
